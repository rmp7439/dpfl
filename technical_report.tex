\begin{abstract}
This report evaluates a Differentially Private Federated Learning (DP-FL) system on CIFAR-10 partitioned across five clients under Dirichlet data heterogeneity ($\alpha \in \{0.1, 10.0\}$). Using Flower and Opacus, we examine privacy--utility tradeoffs across noise multipliers ($\sigma \in \{0.5, 1.0, 1.5, 2.0\}$) and clipping thresholds ($C \in \{0.1, 1.0\}$) under add/remove-one-sample Differential Privacy ($\delta = 10^{-5}$). Centralized non-private training achieves 74.87\% test accuracy (Adam, 30 epochs), while non-private FedAvg achieves 47.38\% (SGD, 15 rounds). Under DP-FL with $\sigma=1.0, C=1.0$ ($\alpha=0.1$, seed 42), the primary 15-round run achieves 26.11\% test accuracy at an accountant-reported estimate of $\varepsilon=2.6974$ under assumed Poisson subsampling. Across three historical runs with nominally identical configurations, final accuracy ranges from 24.41\% to 28.74\%, representing an observed spread of approximately 4.33 percentage points. In privacy grid evaluations, configuring $\sigma=2.0$ with $C=0.1$ attains 30.57\% accuracy at an accountant-reported $\varepsilon=0.9117$. Crucially, centralized and federated baselines differ in optimizer, learning rate, and training budget, precluding attributing the performance gap solely to differential privacy.
\end{abstract}

\section{Introduction and Related Work}

Federated Learning (FL) enables distributed edge devices to collaboratively train a shared machine learning model without centralizing raw data~\cite{mcmahan2017}. Although raw training data remain on local devices, sharing parameter updates or gradients remains susceptible to inference and data reconstruction attacks that can recover private training instances. Differential Privacy (DP), specifically through Differentially Private Stochastic Gradient Descent (DP-SGD)~\cite{abadi2016}, mitigates these risks by bounding individual gradient contributions and injecting calibrated noise.

In this work, we implement and evaluate a DP-FL system for image classification on CIFAR-10 partitioned across five clients using Flower~\cite{flower} for orchestration and Opacus~\cite{opacus} for local private training. We examine how non-IID data distributions, generated via symmetric Dirichlet partitioning, interact with DP-SGD mechanisms, and evaluate the reproducibility and numerical consistency of reported experimental artifacts.

\paragraph{Related Work.}
McMahan et al.~\cite{mcmahan2017} introduced federated averaging as a communication-efficient framework for decentralized deep learning. Abadi et al.~\cite{abadi2016} established DP-SGD, introducing the moments accountant for tight composition. Mironov~\cite{mironov2017} proposed R{\'e}nyi Differential Privacy (RDP) as a relaxation that composes linearly under sequential training steps. Balle et al.~\cite{balle2020} derived the optimal conversion theorem from RDP to $(\varepsilon, \delta)$-DP implemented in Opacus. Under static data partitions, parallel composition~\cite{mcsherry2009} bounds global privacy loss across disjoint client datasets. System orchestration is managed by Flower~\cite{flower}, while Opacus~\cite{opacus} handles per-sample clipping and noise injection.

\section{Background}

\subsection{Federated Learning and FedAvg}
FL coordinates model training over synchronized communication rounds $r \in \{1, \dots, R\}$. At round $r$, a central server broadcasts the current global model parameters $w^r$ to participating clients $k \in \{0, \dots, K-1\}$. Each client trains locally on its local dataset $\mathcal{D}_k$ for $E$ epochs using mini-batch stochastic gradient descent, yielding updated parameters $w_k^{r+1}$. The server aggregates the updates using weighted averaging:
\begin{equation}
    w^{r+1} = \sum_{k=0}^{K-1} \frac{n_k}{N} w_k^{r+1},
\end{equation}
where $n_k = |\mathcal{D}_k|$ and $N = \sum_k n_k$.

\subsection{Differential Privacy and DP-SGD}
A randomized algorithm $\mathcal{M}$ satisfies $(\varepsilon, \delta)$-Differential Privacy (DP) if, for all neighboring datasets $\mathcal{D}, \mathcal{D}'$ differing by the addition or removal of a single training example ($|\mathcal{D} \Delta \mathcal{D}'| = 1$, add/remove-one-sample adjacency), and all measurable output subsets $\mathcal{S}$:
\begin{equation}
    \mathbb{P}[\mathcal{M}(\mathcal{D}) \in \mathcal{S}] \le e^\varepsilon \mathbb{P}[\mathcal{M}(\mathcal{D}') \in \mathcal{S}] + \delta.
\end{equation}
DP-SGD satisfies this guarantee by: (1) computing per-sample gradients $g_i(w) = \nabla_w \ell(w; x_i)$, (2) clipping their $L_2$ norms to a maximum threshold $C$, yielding $\bar{g}_i = g_i / \max(1, \|g_i\|_2 / C)$, and (3) adding calibrated Gaussian noise to the aggregated gradient. Because clipping bounds the contribution of any single example to $\|\bar{g}_i\|_2 \le C$, adding or removing an example changes the summed batch gradient by at most $C$ in $L_2$ norm, establishing global $L_2$ sensitivity $\Delta_2 = C$.

\subsection{Rényi Differential Privacy (RDP)}
Rényi Differential Privacy of order $\alpha_{\text{RDP}} > 1$ characterizes the Rényi divergence of order $\alpha_{\text{RDP}}$ between $\mathcal{M}(\mathcal{D})$ and $\mathcal{M}(\mathcal{D}')$. To prevent confusion throughout this report, we strictly denote the Rényi order as $\alpha_{\text{RDP}}$, distinguishing it from the Dirichlet data heterogeneity parameter $\alpha$. Under sequential composition, RDP values compose linearly: if client $k$ performs $T_k$ physical training steps, its cumulative RDP of order $\alpha_{\text{RDP}}$ is simply the sum of its step-level RDPs.

\section{Threat Model and Privacy Scope}

\paragraph{Sample-Level Privacy.}
The system targets \textbf{sample-level} differential privacy under add-or-remove-one-sample adjacency ($|\mathcal{D} \Delta \mathcal{D}'| = 1$, unbounded differential privacy). The reported privacy bounds quantify the statistical influence of adding or removing an individual CIFAR-10 training image within a client partition under the analytical Sampled Gaussian Mechanism in Opacus, where the per-step $L_2$ sensitivity of the summed clipped gradients is $\Delta_2 = C$. In contrast, substitute-one-sample adjacency (replacing an example, $|\mathcal{D} \Delta \mathcal{D}'| = 2$) would double the sensitivity to $2C$ or require group-privacy inflation, which is not supported by the accountant-reported $\varepsilon$ values. All stated $\varepsilon$ values represent accountant-reported estimates under the assumed Poisson-sampling mechanism rather than a proven end-to-end guarantee for the executed multi-round distributed system. The mechanism does \textbf{not} provide client-level differential privacy; it does not protect the collective dataset of a participating client.

\paragraph{Adversarial Capabilities.}
The threat model assumes an honest-but-curious central server and adversarial participants that observe shared model weights and round-level metrics. The server executes the aggregation protocol faithfully but may attempt to infer private training instances from received client parameters. Adversarial clients may observe global model checkpoints across rounds. Sample-level DP ensures that the presence or absence of any single training image has bounded statistical influence on the published models, mitigating membership inference and sample reconstruction attacks.

\section{Methodology}

\subsection{DP-SGD Mechanism Implementation}
Local training uses Opacus. For each mini-batch drawn with batch size $B$, the mechanism:
\begin{enumerate}
    \item Computes per-sample gradients $g_i$ for each example $i$ in the batch.
    \item Clips each gradient to maximum $L_2$ norm $C$: $\bar{g}_i = g_i / \max(1, \|g_i\|_2 / C)$.
    \item Sums the clipped gradients: $\sum_{i} \bar{g}_i$.
    \item Adds Gaussian noise with standard deviation $\sigma C$ to the summed clipped gradients:
    \begin{equation}
        \tilde{g} = \sum_{i=1}^{B} \bar{g}_i + \mathcal{N}(0, \sigma^2 C^2 I).
    \end{equation}
    \item Normalizes the noisy sum by the expected batch size to obtain the descent step: $g_{\text{step}} = \tilde{g} / B$.
\end{enumerate}
Because Gaussian noise standard deviation is scaled directly by $C$, the effective noise-to-sensitivity multiplier in the accountant is $\sigma = (\sigma C) / C$.

\subsection{Privacy Accounting Chain}
Privacy loss is tracked analytically via the subsampled Gaussian mechanism accountant in Opacus:
\begin{enumerate}
    \item \textbf{Subsampling Rate}: At each local step, client $k$ draws batches with empirical sampling rate $q_k = 1 / \lceil n_k / B \rceil$, where $B=64$ and $n_k$ is the client's local sample count.
    \item \textbf{Sequential RDP Composition}: Over $T_k$ cumulative physical local steps across rounds, RDP accumulates linearly under adaptive composition:
    \begin{equation}
        \text{RDP}_{T_k}(\alpha_{\text{RDP}}) = T_k \cdot \text{RDP}_{\text{step}}(\alpha_{\text{RDP}}, q_k, \sigma).
    \end{equation}
    \item \textbf{Conversion to $(\varepsilon, \delta)$-DP}: Cumulative RDP is converted to $(\varepsilon, \delta)$-DP at fixed $\delta = 10^{-5}$ via the optimal conversion theorem~\cite{balle2020}:
    \begin{equation}
        \varepsilon_k(\delta) = \min_{\alpha_{\text{RDP}} > 1} \left[ \text{RDP}_{T_k}(\alpha_{\text{RDP}}) - \frac{\log \delta + \log \alpha_{\text{RDP}}}{\alpha_{\text{RDP}} - 1} + \log\left(\frac{\alpha_{\text{RDP}} - 1}{\alpha_{\text{RDP}}}\right) \right].
    \end{equation}
    \item \textbf{Disjoint Partitions and Parallel Composition}: The full training dataset $\mathcal{D}$ is partitioned into pairwise disjoint client subsets $\mathcal{D}_0, \dots, \mathcal{D}_{K-1}$ with $\mathcal{D}_j \cap \mathcal{D}_k = \emptyset$ for $j \ne k$. Under add/remove-one-sample adjacency, an added or removed training example affects the local dataset of exactly one client $k^*$, while all other client datasets $\mathcal{D}_j$ ($j \ne k^*$) remain identical ($\mathcal{D}_j = \mathcal{D}'_j$). At any communication round, only client $k^*$ directly queries the partition containing the sample; other clients $j \ne k^*$ access the sample solely through the broadcast global model parameters $w^r$, which acts as post-processing of earlier privatized updates. Client $k^*$ adaptively composes its local DP-SGD queries over $R$ rounds under RDP, and server-side FedAvg aggregation is a linear combination operating as post-processing. Consequently, under these modeling assumptions, the dataset-level privacy loss is bounded by the worst-case individual client:
    \begin{equation}
        \varepsilon_{\text{global}} = \max_{k \in \{0, \dots, K-1\}} \varepsilon_k.
    \end{equation}
    Under this formulation, the worst-case client is the client with the \textbf{smallest} local sample count $n_k$ (Client 4 under $\alpha=0.1$), because its higher sampling rate $q_k = 1/88$ drives faster privacy expenditure, yielding $\varepsilon_4 = 2.6974$. This global bound represents an accountant-reported analytical estimate under the assumed Poisson-sampling model; it relies on these composition assumptions and does not constitute a formal end-to-end mathematical proof of the full interactive system.
\end{enumerate}

\section{Experimental Setup}

\subsection{Hardware and Execution Environment}
All reported experiments were executed on CPU using Ray single-machine virtual-client process simulation rather than a physical distributed deployment.

\subsection{Model Architecture}
We evaluate SimpleCNN with GroupNorm, designed to preserve sample independence (avoiding BatchNorm, which leaks cross-sample statistics):
\begin{itemize}
    \item Three convolutional layers ($3 \to 16 \to 32 \to 64$ channels, $3\times 3$ kernels, padding 1).
    \item GroupNorm with 4 groups following each convolutional layer.
    \item ReLU activations and $2\times 2$ MaxPool layers.
    \item Fully connected layers ($64 \times 4 \times 4 \to 128 \to 10$) with Dropout ($p=0.5$).
\end{itemize}

\subsection{Data Partitioning}
CIFAR-10 (50,000 training, 10,000 test images across 10 classes) is partitioned across 5 clients using a symmetric Dirichlet distribution parameterized by $\alpha$:
\begin{itemize}
    \item \textbf{Allocation vs. Class Support}: Individual images are assigned to disjoint client datasets; client datasets do not have disjoint classes, but rather class distributions overlap across clients while individual sample indices are strictly disjoint.
    \item \textbf{$\alpha = 0.1$ (High Heterogeneity)}: Client sample sizes are $[12944, 10514, 11934, 9029, 5579]$. The empirical heterogeneity metric (mean standard deviation of class counts across clients) is 1699.28.
    \item \textbf{$\alpha = 10.0$ (Near-IID)}: Client sample sizes are $[8856, 10009, 10553, 10399, 10183]$, with an empirical heterogeneity metric of 236.88.
\end{itemize}

\section{Results}

\subsection{Centralized and Non-Private FedAvg Baselines}
The centralized baseline achieves \textbf{74.87\%} test accuracy after 30 epochs of Adam optimization (learning rate 0.001). Non-private FedAvg achieves \textbf{47.38\%} test accuracy after 15 communication rounds under $\alpha=0.1$ data heterogeneity (SGD, learning rate 0.05, 1 local epoch per round). 

\paragraph{Confounded Baseline Comparison.}
The 27.49 percentage-point difference between the centralized baseline (74.87\%) and non-private FedAvg (47.38\%) does not represent the cost of differential privacy or data heterogeneity alone. The comparison is confounded by optimizer (Adam with cosine annealing vs. SGD), learning rate (0.001 vs. 0.05), training budget (30 epochs vs. 15 rounds of 1 local epoch), and federated aggregation dynamics. Likewise, the comparison between non-private FedAvg and DP-FL is confounded by momentum (0.0 vs. 0.9). No near-IID non-private FedAvg baseline was established, precluding causal isolation of these factors.

\subsection{Main DP-FL Result (Stage 4)}
The primary Stage~4 DP-FL configuration ($\alpha=0.1, \sigma=1.0, C=1.0$, seed 42) attains a final test accuracy of \textbf{26.11\%} (with a best round accuracy of 27.29\% at round 14) and an accountant-reported cumulative privacy bound of $\varepsilon = 2.6974$ ($\delta=10^{-5}$, minimizing Rényi order $\alpha_{\text{RDP}}=6.9$).

\paragraph{Non-Monotonicity and Clipping Dynamics.}
The grid results refute the blanket assumption that increasing $\sigma$ uniformly degrades accuracy across all configurations:
\begin{itemize}
    \item For $C=0.1$, final accuracy remains remarkably stable across noise scales: 30.61\% ($\sigma=0.5$), 32.01\% ($\sigma=1.0$), 32.06\% ($\sigma=1.5$), and 30.57\% ($\sigma=2.0$). In this grid, configuring $\sigma=2.0$ with $C=0.1$ attains \textbf{30.57\%} test accuracy at a formal bound of $\varepsilon = 0.9117$. However, this is an empirical observation from a single training run (seed 42).
    \item Conversely, for $C=1.0$, accuracy drops steeply as noise increases: from 36.49\% ($\sigma=0.5$) down to 28.74\% ($\sigma=1.0$), 17.27\% ($\sigma=1.5$), and 18.37\% ($\sigma=2.0$).
\end{itemize}
Figure~\ref{fig:stage5_tradeoff} illustrates these distinct trajectories. The observed results demonstrate that formal privacy bounds below $\varepsilon < 2.0$ do not mathematically prevent accuracy from reaching 30\%, but they do not establish a causal effect of clipping threshold $C$ independently of effective step size and gradient signal-to-noise ratio.

\paragraph{Evaluation Findings.}
\begin{enumerate}
    \item \textbf{Accounting Agreement}: All three runs exhibit identical privacy accounting metrics: $\varepsilon = 2.6974$ at $\delta=10^{-5}$, minimizing Rényi order $\alpha_{\text{RDP}} = 6.9$, and client 4 governing the global bound ($T_4 = 1320$ steps, $q_4 = 1/88$).
    \item \textbf{Observed Accuracy Spread}: Across the three executions, final test accuracy ranges from 24.41\% to 28.74\%, representing an observed spread of approximately 4.33 percentage points. This spread reflects empirical variability across historical runs conducted before deterministic seeding was formalized across client worker processes; it is an observed sample range, not a formal noise floor or statistical confidence interval.
    \item \textbf{Historical Non-Determinism}: All three executions predated the repository's deterministic seeding architecture (detailed in Appendix~\ref{sec:reproducibility}). Prior to that fix, the federated pipeline lacked per-round client seed derivation, isolated DataLoader RNG generators, and deterministic server aggregation sorting across Ray actor processes. In addition, minor runner script refactorings occurred across stages. Consequently, identical nominal seeds did not yield identical historical trajectories.
    \item \textbf{Attribution and Reproducibility}: Because multiple software factors evolved across early stages, the exact causal attribution of accuracy differences cannot be conclusively isolated from historical artifacts alone. Historical runs cannot be reproduced bitwise; determinism has been demonstrated solely on post-patch integration tests (Appendix~\ref{sec:reproducibility}).
\end{enumerate}

\section{Discussion}

\paragraph{Privacy Budget vs. Model Utility.}
Our empirical findings demonstrate that formal privacy bounds do not map monotonically to classification accuracy:
\begin{itemize}
    \item In Stage~5, configuring $\sigma=2.0$ with $C=0.1$ achieved \textbf{30.57\%} test accuracy at an accountant-reported $\varepsilon = 0.9117$ in a single run, without establishing a causal effect or a general guarantee.
    \item In Stage~6, the near-IID configuration ($\alpha=10.0, \sigma=1.0, C=1.0$) achieved \textbf{31.51\%} accuracy at $\varepsilon = 2.0691$ in a single run.
\end{itemize}
Model utility depends intricately on gradient clipping norm $C$, local gradient variance, and optimization dynamics, rather than differential privacy budget $\varepsilon$ in isolation. Moreover, the observed results do not establish a causal effect of clipping threshold $C$ independently of other training factors. Clipping interacts directly with effective learning rate, gradient signal-to-noise ratio, and batch variance; varying $C$ without retuning the learning rate simultaneously shifts both the optimization step size and the injected noise scale.

\paragraph{Finite-Horizon Evaluation.}
The 15-round runs provide empirical measurements over a 15-round horizon on CPU. They do not demonstrate asymptotic convergence. Extended training horizons and systematic learning rate scheduling would be required to evaluate long-term convergence behavior.

\section{Limitations}

\begin{enumerate}
    \item \textbf{Privacy Scope and Adjacency}: The privacy guarantee strictly targets individual CIFAR-10 training images under add-or-remove-one-sample adjacency (sample-level DP), not entire participating clients or institutions.
    \item \textbf{Sampling Mechanism and Accountant Assumptions}: Poisson subsampling denotes independent per-example inclusion (Bernoulli trials with probability $q$), not sampling with replacement. Although Opacus wraps the loader in its Poisson sampler (\texttt{Uniform\-With\-Replacement\-Sampler}, executing independent Bernoulli inclusion per step), the stated $\varepsilon$ values represent accountant-reported estimates under the assumed Poisson-sampling mechanism. The end-to-end formal guarantee for the executed multi-round sampling procedure and model-sharing protocol has not been established.
    \item \textbf{Multi-Round Composition and Verification}: Global privacy bounds rely on disjoint client data partitions and post-processing across communication rounds. This reasoning assumes the accountant's analytical model applies without side channels; it has not been verified by an empirical privacy audit (such as membership inference attacks or canary gradient reconstruction) or a formal external mathematical proof.
    \item \textbf{Secure Random Number Generation}: For simulation efficiency, Opacus cryptographically secure RNG was disabled (\texttt{secure\_rng=False}). Production deployments requiring formal differential privacy must enable cryptographically secure RNG.
    \item \textbf{Hyperparameter Tuning and Causality}: Federated learning rates and momentum were kept fixed across DP runs without DP-specific tuning due to CPU computational constraints. Observed performance differences between clipping thresholds cannot be interpreted as isolated causal effects.
    \item \textbf{Multi-Seed Horizon}: Multi-seed runs were limited to 3 communication rounds and 3 seeds, serving as preliminary variance checks rather than asymptotic proofs.
\end{enumerate}

\section{Conclusion}

We conducted an empirical evaluation and reproducibility analysis of Differentially Private Federated Learning on CIFAR-10 across 5 clients. On full CIFAR-10, centralized non-private training reaches 74.87\% accuracy (Adam, 30 epochs), non-private FedAvg achieves 47.38\% accuracy (SGD, 15 rounds), and DP-FL attains 26.11\% accuracy at an accountant-reported estimate of $\varepsilon=2.6974$ under assumed Poisson subsampling ($\sigma=1.0, C=1.0$, 15 rounds). Across three historical runs with nominally identical configurations, final accuracy ranged from 24.41\% to 28.74\%, an observed spread of approximately 4.33 percentage points. Grid evaluations demonstrated that $\sigma=2.0$ with $C=0.1$ attained 30.57\% accuracy at an accountant-reported $\varepsilon=0.9117$ in a single run, though this does not isolate a causal effect of clipping threshold $C$. Direct baseline comparisons remain confounded by optimizer choice and training budgets. These findings emphasize the necessity of rigorous empirical accounting, transparent provenance, and disciplined qualification of variability in private federated learning systems.

\section{Reproducibility Architecture and Verification}
\label{sec:reproducibility}

\subsection{Deterministic Seeding Architecture}
Prior to commit \texttt{08ad3f8} on October 11, 2026, experimental executions across Stages 4, 5, and 6 (conducted between October 7 and October 9, 2026) lacked deterministic worker seeding, per-round client seed derivation, and isolated DataLoader RNG generators. This historical non-determinism likely contributes to the observed 4.33 percentage-point spread across nominally identical runs. In commit \texttt{08ad3f8}, determinism was formalized in \texttt{run\_federated.py}:
\begin{itemize}
    \item \textbf{Root Initialization}: Seeds Python \texttt{random}, NumPy, and PyTorch RNGs using base seed.
    \item \textbf{Per-Client Seeding}: Deterministically derives an integer seed via SHA-256:
    \begin{equation}
        \text{seed}_{k, r} = \text{int}\Big(\text{SHA256}(s_{\text{base}} : k : r)[:4]\Big) \ \& \ \text{0x7FFFFFFF}.
    \end{equation}
    \item \textbf{Isolated Generator}: Passes an isolated \texttt{torch.Generator} to DataLoader shuffling and Opacus \texttt{make\_private}.
    \item \textbf{Deterministic Initial Model}: Initializes the initial global model from a seeded instance and passes it to the server strategy as \texttt{initial\_parameters}.
    \item \textbf{Deterministic Aggregation}: In \texttt{CheckpointingFedAvg.aggregate\_fit()}, incoming client results are sorted deterministically by numeric client ID before averaging.
\end{itemize}

\subsection{Integration Verification Artifacts}
Reproducibility was verified across two-round integration runs in \texttt{results/reproducibility/}:
\begin{itemize}
    \item \textbf{Run A vs. Run B (Seed 42)}: Both runs produced identical initial model hash (\texttt{00c43041...}), identical final model hash (\texttt{e23b740f...}), identical cumulative epsilon ($\varepsilon = 4.442963$), identical best Rényi order (4.1), identical total DP steps (30), and identical per-round accuracy (13.5\% round 1, 12.5\% round 2).
    \item \textbf{Divergence Check (Seed 43)}: Seed 43 produced distinct initial and final model hashes, different accuracy (7.5\%), and different epsilon ($\varepsilon = 4.696514$), while maintaining structural step count agreement (30 total DP steps).
\end{itemize}
